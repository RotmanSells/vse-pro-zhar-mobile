# VPZH-030 — решение по изображениям товара

Статус: основная часть решений подтверждена; ожидаются решения по production-хранилищу,
ограничениям файла, обработке размеров и кэшированию.

Этот файл — рабочая запись решений для последующего составления manifest и плана задачи
VPZH-030. Реализация, выбор провайдера и изменения API до завершения решений не начинаются.

## Вопросы

1. У товара должна быть одна главная картинка или несколько картинок/галерея?
2. Картинка обязательна для товара или товар может быть без картинки?
3. Кто загружает картинку: только Admin или ещё кто-то?
4. Откуда Admin выбирает картинку: загрузка файла с компьютера, ссылка на готовую картинку или оба варианта?
5. Где храним картинки: пока только локально для разработки/тестов или сразу нужен production-вариант хранения?
6. Какие форматы разрешить: JPG, PNG, WebP? Нужны ли другие?
7. Какой максимальный размер файла и максимальные размеры картинки?
8. Можно ли заменить картинку? Нужно ли уметь удалить её и показать placeholder?
9. Нужно ли автоматически уменьшать/обрезать картинку или сохраняем файл как загрузили?
10. Должна ли картинка быть доступна всем гостям только для видимых товаров?
11. Нужно ли отдельно настраивать кэширование картинок или достаточно обычного URL/ответа Backend?

## Ответы владельца

1. Одна главная картинка.
2. Картинка обязательна.
3. Загружает только Admin.
4. Только загрузка файла.
5. Для production подходит отдельное object storage.
6. JPG, PNG и WebP; после загрузки сохраняем результат в WebP.
7. Подходит ограничение: исходный файл до 10 MB, результат максимум 1600×1600 px.
8. Картинку можно заменить и удалить.
9. Подходит resize без crop, чтобы не обрезать фотографию.
10. Картинка доступна гостям только у видимых товаров.
11. Подходит стандартное кэширование картинок.
12. Удаление разрешено только вместе с загрузкой новой картинки.

## Что осталось решить

- Production-хранилище: подтверждено отдельное объектное хранилище, а не диск API-сервера.
- Ограничения: подтверждены входной файл до 10 MB и результат WebP до 1600×1600 px.
- Resize/crop: подтвержден resize без crop, чтобы не терять часть фотографии.
- Кэширование: приложение временно сохраняет уже загруженную картинку, чтобы повторно открывать
  её быстрее и не скачивать каждый раз. Рекомендуется стандартное кэширование по URL.
- Картинка обязательна; удаление разрешено только вместе с загрузкой новой картинки.
- Кэширование: подтверждено стандартное кэширование по URL.
